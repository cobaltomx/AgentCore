## Bloque 1 — Bugfixes de backend (sesión previa, resumida)

### 1.1 Agente dice "Un momento" y cuelga

**Causa raíz:** `voice-agent.js` enviaba los resultados de herramientas en formato OpenAI (`role: 'tool'`) en lugar del formato Anthropic.

**Fix — `backend/src/agents/voice-agent.js`:**
```js
// Formato correcto Anthropic para tool results
const assistantBlocks = [];
if (responseText) assistantBlocks.push({ type: 'text', text: responseText });
for (const tc of llmResult.toolCalls) {
  assistantBlocks.push({ type: 'tool_use', id: tc.id, name: tc.name, input: tc.input });
}
const toolResultMessages = [
  ...messages,
  { role: 'assistant', content: assistantBlocks },
  {
    role: 'user',
    content: toolResults.map((tr, i) => ({
      type: 'tool_result',
      tool_use_id: llmResult.toolCalls[i].id,
      content: JSON.stringify(tr.result || { error: tr.error }),
    })),
  },
];
```

### 1.2 Redis `ERR syntax error` — ioredis

**Causa:** `redis.set(key, val, { EX: 120 })` — ioredis no acepta objeto de opciones, serializa `[object Object]`.

**Fix — `backend/src/routes/webhooks/twilio.js`:**
```js
// Correcto:
await app.redis.set(resultKey, JSON.stringify(payload), 'EX', 120);
// También en el catch anidado:
await app.redis.set(resultKey, JSON.stringify({ error: true }), 'EX', 60);
```

### 1.3 `userMessage.toLowerCase is not a function`

**Causa:** Después del fix de tool results, `messages` puede tener `content` como array en lugar de string.

**Fix — `backend/src/services/llm-router.js`:**
```js
const lastUserContent = messages.filter(m => m.role === 'user').pop()?.content || '';
const lastUserMsg = typeof lastUserContent === 'string'
  ? lastUserContent
  : Array.isArray(lastUserContent)
    ? lastUserContent.filter(b => b.type === 'text').map(b => b.text).join(' ')
    : '';
```

### 1.4 Horarios en la madrugada

**Causa:** El contenedor Docker corre en UTC. `date.setHours(9, 0, 0, 0)` = 09:00 UTC = 04:00 AM Mexico City (CDT = UTC-5).

**Fix — `backend/src/services/scheduling/calcom-client.js`:**
```js
// Usar Intl API para calcular offset correcto por slot
const dateStr = dayUtc.toLocaleDateString('sv-SE', { timeZone: timezone }); // "YYYY-MM-DD"
const nominalUtc = new Date(`${dateStr}T${hour}:${min}:00Z`);
const localH = parseInt(nominalUtc.toLocaleString('en-US', { timeZone: timezone, hour: '2-digit', hour12: false }));
let shift = hour - localH;
if (shift > 12) shift -= 24;
if (shift < -12) shift += 24;
const slotDate = new Date(nominalUtc.getTime() + shift * 3600000);
```

### 1.5 Latencia del agente

- **LLM routing:** Haiku (`claude-3-5-haiku-20241022`) para turnos simples, Sonnet (`claude-sonnet-4-20250514`) para agendamiento/ventas/complejos.
- **max_tokens reducido a 512** para respuestas de voz más cortas y rápidas.
- **Polling Redis reducido a 200ms** (antes 400ms).
- **Fillers inteligentes:** Si la query contiene palabras de agendamiento, usa filler específico. Si no, aleatorio.
- **Skip Cartesia TTS** para respuestas cortas (< 90 chars) — usa Twilio TTS nativo.

```js
const FILLERS = ['Claro, un momento.', 'Permítame.', 'Sí, con gusto.', 'Un momento.', 'Claro que sí.'];
const isSchedulingQuery = /agend|cita|dispon|horario|reserv|cu[aá]ndo|mañana|semana/i.test(transcript);
const fillerText = isSchedulingQuery
  ? 'Déjame consultar nuestra agenda de citas, un momentito por favor...'
  : pickFiller();
```
